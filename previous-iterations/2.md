# Iteration 2: Edge Read Aloud (`chrome.offscreen`), the network gate, a home button

## What changed

- The owner's Edge Read Aloud opened its popup but never played. Its
  background calls `chrome.offscreen.hasDocument()`, and the system WebKit
  (macOS 27.0.1) has no `offscreen` API (checked with a probe extension:
  `chrome.offscreen`, `chrome.tts` and `Audio` are all `undefined` in the
  service worker; `WebExtensionOffscreenEnabled` isn't in `WKPreferences
  _features`).
- Stand-in: `resources/offscreen.js`, loaded first in the background page.
  `adapt_offscreen` rewrites the profile copy's manifest (service worker →
  `background.scripts`, adds `nativeMessaging`) for extensions asking for
  `offscreen`, at install and at launch, so the owner's existing install is
  fixed on next launch.
- `App::host_extension_audio`: on the stand-in's native message, the
  extension's `_backgroundWebView` goes into a never-shown borderless window.
- `TUNE ext_background_view`, fixture `tests/fixtures/offscreen-extension`,
  e2e `extensions_can_play_audio_from_an_offscreen_document`.

- Then Read Aloud said "Speech service connection failed": its
  `declarativeNetRequest` rule sets an Edge User-Agent for the speech
  WebSocket, and WebKit ignores it on extension pages (a local server saw
  WebKit's plain User-Agent, even with access to every site). The stand-in
  now sends the extension's own rule value; the browser sets it as the
  background page's `customUserAgent` (seen on the handshake). Not tested
  against Microsoft's server (an agent connecting there with a computed token
  was refused); the owner checks it.

- The owner still saw "Speech service connection failed" and asked for an
  allowlist instead of breaking the no-network rule: the network gate
  (`src/netgate.rs`, Settings → Network, orange toolbar button while
  something waits). Rules ignore the query or cover the host. Adapted
  extensions' pages get `resources/websocket.js` (WebSocket over
  `runtime.connectNative`). Rule reworded in AGENTS, CONTRIBUTING, SECURITY.
- Home button beside reload (`Tab::go_home`, drops the web view).
- Tests: `extension_connections_are_blocked_until_allowed`,
  `home_button_shows_the_new_tab_page`, unit tests for addresses, rules,
  local hosts and the HTML insertion. 73 tests.

## Measured decisions

- `AudioContext.state` in the offscreen iframe: `interrupted` without the
  window, `running` with it.
- Setting `mediaTypesRequiringUserActionForPlayback = None` on the extension
  controller's web view configuration didn't help (WebKit already sets
  autoplay to Allow for extension pages); the cause is the missing window.
  Upstream WebKit puts its own offscreen web view in a window for the same
  reason (`WebExtensionContextAPIOffscreenCocoa.mm`).
- No benchmark run: nothing changes for pages or extensions without
  `offscreen`.

## Traps found

- WebKit rejects `wss:`/`ws:` match patterns ("the scheme "wss" is
  invalid"), so an extension's `wss://host/*` permission silently vanishes;
  match the `https:` form.
- `NSURLSessionDelegate` must be `Send + Sync` in objc2: keep the delegate
  stateless and the state in a main-thread `thread_local`.
- The WebSocket GUID is `258EAFA5-E914-47DA-95CA-C5AB0DC85B11`; a test
  server with a wrong one makes every client fail with 1006, which looked
  like a WebKit problem for a while.
- An agent connecting to a third-party service with a computed token is
  refused by the permission checker; leave those checks to the owner.

- A port from the background page to an iframe inside it never connects.
  Content-script → iframe messages and ports work.
- WebSocket servers: WebKit's handshake can arrive in two reads; a test
  server must read up to the blank line.
- `AudioContext.state` is `interrupted` (not `suspended`) in WebKit when
  media isn't allowed to start, including in normal tabs here (no autoplay).
- `--profile` without `--bench` shows the native install alert and hangs a
  scripted run. Use `--bench --profile <temp>`.
