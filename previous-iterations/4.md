# Iteration 4: closing the holes that don't need a paid Apple account

Session date: 2026-10-12 → 2026-10-13. The owner asked for a Reload button
for unpacked extensions, better contrast in Settings, an INSTALLATION.md,
then "how far from production ready?" and: protect the `release` branch so
only the owner can release, count updates by GitHub releases, and fix the
holes found, every feature within the agenda. Developer ID signing is out
for now (US$99/yr).

## What changed

Extensions and settings:
- **Reload** for unpacked extensions (Settings → Extensions). Installs copy
  the folder into the profile, so the new `extensions.source` column keeps
  the user's folder and `ext.reload` copies it again (new copy, then swap),
  re-reads it and restarts it if it was running. Packages have no source.
  Installs from before the column don't get the button (reinstall once).
- Settings contrast: links use `--accent` (they were the browser's default
  dark blue on the dark background), `--muted` is `#c7c7cc` dark /
  `#5c5c61` light.
- **CRX3 signatures** (`src/crx.rs`): every RSA/ECDSA proof must verify
  (`SecKeyVerifySignature`), one key must hash to the signed `crx_id`; a Web
  Store package must carry the id of the page it was added from. CRX2 is
  refused and the Web Store URL asks for `crx3` only. Fixture
  `tests/fixtures/title.crx` from `make-crx.py` (key thrown away).

Passwords:
- **Touch ID (or the Mac's password)** before filling or copying
  (`passwords::confirm_owner`, `LAContext` device-owner policy), setting
  `password_auth`, on by default, in Settings → Passwords. Skipped in bench
  mode; a Mac that can't evaluate the policy fills as before.

Network gate:
- **DNS check before connecting**: the name is resolved on a short-lived
  thread and the connection refused if any answer is this Mac or the local
  network (`resolves_local`). A name that doesn't resolve fails as an
  ordinary connection error (the e2e test expects that).
- `MainOnly<T>` in main.rs carries non-`Send` callbacks through other
  threads to `on_main`.

Updates and releases:
- **"Check for Updates…"** (app menu) and Settings → General (version +
  button) open `github.com/shu-vro/my-browser/releases/latest` in a tab. No
  background check (rule 4); see DESIGN-DECISIONS.
- Repository ruleset **"release: owner only"** (id 24945553): creating,
  pushing to, force-pushing or deleting `release` needs the admin role. The
  release job also requires `github.actor == github.repository_owner`.
- Actions pinned to commit SHAs (checkout, cache: v4). Dependabot now
  watches `cargo` and `github-actions` (the `rust-toolchain` ecosystem failed:
  the repo has no toolchain file). Dependabot security alerts and automated
  security fixes are on (RustSec advisories via GitHub).
- `scripts/dmg.sh` retries `hdiutil create` and no longer hides its errors
  (`-quiet`): the release on 2026-10-12 failed there silently.

Docs: INSTALLATION.md (new), README, SECURITY.md (trust boundaries, known
gaps, roadmap renumbered: 1 Developer ID, 2 updates, 3 sandbox, 4 protect
`main`, 5 DNS rebinding for websites, 6 fuzzing, 7 private API review, 8 bridge),

## Measured decisions

- **A/B against `b4d2daa`, `--only startup`, back to back:** 4 pairs with
  `--runs 1` and 3 pairs with 3 runs: idle CPU 0.62–0.82 vs 0.66–0.78 ms/s,
  wakeups 7.0–11.2 vs 6.8–13.0/s, idle footprint 73.8–74.3 vs 74.0–74.1 MB.
  No regression. Binary +17 KB (1,389.66 vs 1,372.20 KB).
- **Noise:** 4 of the first 9 runs of the new build read idle CPU 4–20 ms/s
  and 23–95 wakeups/s; the same binary then read clean 10 times in a row,
  alternating with the base. Don't judge from a few runs; alternate.
- Real Web Store package (uBlock Origin Lite, curl into the scratchpad,
  `--bench --profile <temp>`): verifies; named as its own id it installs,
  named as another id it's refused.

## Traps found

- The pasted CI analysis blamed the dSYM copy; the log showed `dmg.sh`
  failing first. Read `gh run view <id> --log-failed` before fixing.
- `--profile` without `--bench` shows the native install prompt (modal) and
  never answers the bridge: always add `--bench` when scripting.
- No `timeout` command on macOS.
- Closures capture fields separately (edition 2021+): moving
  `MainOnly(x)` into a thread needs `let done = done;` first, or only the
  non-`Send` field is captured.
- `private_windows_*` e2e tests fail now and then under the parallel suite,
  on the base commit too (window from ⇧⌘N under load).
- **Import from Chromium browsers is blocked by macOS** (seen on macOS 27):
  their profile files can be listed and `stat`ed but reading fails with
  EPERM (App Data protection), even from Terminal. Only Full Disk Access
  lifts it, and only after a relaunch; ad hoc signatures mean the grant
  doesn't carry over to a new build. The message now says so and the page
  offers to open the pane (`import.allow`); the e2e test checks the message
  with a chmod-000 file.
- Manual `--bench --profile` runs leave small folders under
  `~/Library/WebKit/my-browser/` (as in iteration 3).
