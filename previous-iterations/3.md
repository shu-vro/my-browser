## Measured decisions

- **A/B against the session's starting commit** (`d942fea`), back to back,
  3 runs each, twice: idle CPU 0.30–0.33 vs 0.36–0.38 ms/s, idle wakeups
  8.4–8.6 vs 9.2–10.6/s, anim CPU 0.26–0.31 vs 0.38–0.40 ms/s, anim wakeups
  6.8–8.2 vs 9.4–9.6/s: no regression. Costs: idle footprint +1.2 MB
  (73.9–74.5 vs 73.0–73.1), shell +0.7 MB (31.4–31.7 vs 30.8–30.9), binary
  +230 KB (1,388,544 vs 1,153,344 bytes). The password script is 0.1–0.5 MB
  of the idle cost (`MYB_TUNE=passwords_script=0`).
- **The full benchmark run read idle wakeups 34/s and anim 85/s for the new
  build, and anim 24/s for the old one, an hour apart.** Same builds in the
  A/B: 8 and 9. Full-run activity numbers aren't trustworthy on a busy Mac;
  A/B with `--only` is.
- `bars.tsv` is stale (recorded hidden in iteration 0): almost every visible
  metric "regresses" against it for both builds.
- Web notifications: WebKit asks the permission delegate only with a
  persistent store, and never displays anything for a third-party app, with
  or without `BuiltInNotificationsEnabled` (Swift probe). Dropped by the owner.
- Passwords.app: `PasswordManagerBrowserExtensionHelper` has parent launch
  constraints for Chrome/Edge/Firefox only.
- `getDisplayMedia` refuses hidden pages with InvalidStateError; the focus
  requirement wasn't the problem.
- Element fullscreen is off by default in WKWebView: YouTube's fullscreen
  button did nothing before this session.

## Traps found

- The pre-commit hook needs `cargo fmt` first; it will refuse otherwise (good).
- `WKDownload.originalRequest` is the post-redirect request: Web Store
  packages come from `clients2.googleusercontent.com`. Match by file name.
- WebKit cancels a download whose destination file exists.
- `loadHTMLString` with the page's own URL as base *replaces* the history
  entry: leaving reader mode reloads instead of going back.
- Two extension installs in the same second with the same folder name
  collided (fixed: `<ms>-<n>-<name>`).
- Bench output from scripts races with events they cause (EVAL vs DIALOG,
  PASSWORDS); `Browser::wait_all` takes them in any order.
- `/script/<js>` test pages run before `<body>` exists.
- Form test pages navigate to `welcome?username=…`: wait for it before the
  next `go`, or the late navigation interrupts yours.
- With 12 browsers launching at once, extension startup can exceed 10 s;
  `state_until` waits 20 s now. Under that load, `--on-top` windows cover
  each other (a covered page is "hidden": wait for `visibilityState`), a
  hidden bench window can get a late "became key" for the previous tab
  (select tabs explicitly), and fixed sleeps fail (poll instead). Ten full
  parallel runs in a row passed after these fixes.
- Manual Web Store checks used `--bench --profile $(mktemp -d)`; each left a
  small `~/Library/WebKit/my-browser/WebsiteDataStore/<id>` and
  `WebExtensions/<ID>` folder (not deleted: that folder is shared with the
  owner's unbundled profile, so only the tests' own cleanup deletes by id).
  One `.crx` landed in `~/Downloads` before the redirect fix; deleted.
