> devtools. Just extensions will suffice. … It's not for a software engineer.
> It's for someone who has a memory fetish."

Later requests in the same session:

- "If you see a corner to make this even more performance efficient, do that."
- "Make sure that no monitoring or tracking is ever accepted."

## Stack decision

**A native Rust shell on the system WKWebView, macOS only.**
- Rust with `objc2`, `objc2-app-kit`, `objc2-foundation`, `objc2-web-kit` and
  `block2`.
- `rusqlite`, linked against the system's libsqlite3.

Why:
- Measured: about 85–95% of a browser's memory belongs to the engine running
  the page, not to the browser's own UI.
- WKWebView is already loaded and shared by the OS, has `WKWebExtension`
  support (macOS 15.4+), and has hidden memory switches we can use.
- We considered and rejected:
  - **Chromium/CEF:** heavy.
  - **Servo/Ladybird:** not production-ready.
  - **Our own engine:** a decade of work, and it can't hold the same page in
    less memory.

The owner asked whether building core parts ourselves would be faster. The
answer, with data, is in the "Why not our own engine" section of
docs/ARCHITECTURE.md.

## What exists now

| Area | State |
|---|---|
| Window and UI | Native AppKit. Each tab is a native macOS window tab with back/forward/reload-stop buttons and an address bar that shows the URL. The page title is the window title. |
| Tabs | New, close, reopen closed, Cmd+1..9, Ctrl+Tab, Cmd+Shift+[ ]. Background tabs **sleep**: the web view and its page process are destroyed and the URL and title are kept. They sleep after N minutes (setting, default 5), or all at once when macOS reports memory pressure. Clicking a sleeping tab reloads it. |
| Session | Tabs are restored at launch **asleep**, in the same order, with the same tab selected. Only that tab loads. |
| Profiles | Persistent profile in `~/Library/Application Support/my-browser/` (`browser.db` plus a lock file). Cookies and site data live in WebKit's per-profile store (`WKWebsiteDataStore(forIdentifier:)`), keyed by a UUID kept in browser.db. `--profile DIR` selects another profile. `--bench` without `--profile` gets a throwaway in-memory profile. Only one running browser per profile (file lock). |
| Privacy | Intelligent Tracking Prevention on, all third-party cookies blocked, ad-click attribution off, safe-browsing lookups off by default, and a built-in tracker blocker (Disconnect list, 4,042 rules, compiled into WebKit's content blocker). No page loads before the blocker is attached. The browser sends nothing anywhere. |
| Internal pages | `mybrowser://settings` with sections #general, #privacy, #history, #downloads, #extensions. They talk to Rust over a script-message bridge. Only the top-level frame of a `mybrowser:` page may use it, and web pages can't navigate to or frame internal pages. |
| History | SQLite. Searchable, delete one, clear all. Only http(s) pages are recorded. |
| Downloads | WKDownload. Saved to ~/Downloads or a chosen folder. File names are sanitized and made unique (`file (2).txt`). There's a list with progress, open, show in Finder, cancel and remove. |
| Extensions | Unpacked WebExtensions, installed from a folder and copied into the profile. Their requested permissions are granted at install. Enable, disable and remove. Tabs and windows are exposed to extensions, which content scripts need. |
| Shortcuts | All in the menu bar (see `build_menu` in src/main.rs). |
| Popups, alerts, file picker | target=_blank and window.open open a new tab. alert/confirm/prompt appear as sheets. `<input type=file>` opens the native picker. |
| Bundle | `scripts/bundle.sh` builds a signed `.app` with camera, microphone and location usage strings. |
| Benchmarks | `benchmark/bench.rs` harness with recorded bars in `benchmark/bars.tsv`. **The bars are stale; see Open items.** |
| Tests | 43 total: 8 bench-harness unit, 12 browser unit, 23 end-to-end that drive the real browser. Green several runs in a row at the end of the session. |
| Docs | README.md, docs/ARCHITECTURE.md, docs/DESIGN-DECISIONS.md (how/why Q&A), CONTRIBUTING.md, SECURITY.md, AGENTS.md (CLAUDE.md imports it), benchmark/README.md, tests/README.md |

## Measured decisions

Every number is from the bench harness on this Mac (Apple Silicon, 24 GB,
macOS 27).

**Release profile** (`lto`, `codegen-units=1`, `panic=abort`, `strip`):
binary 548 KB → 362 KB (−34%). Memory didn't change; code size isn't RAM.

**Our own process** is 28 MB at idle, and almost none of it is our code. About
9.6 MB of live heap belongs to Apple frameworks (CoreFoundation strings,
Objective-C class caches, CoreSVG icon data). The rest is freed memory the
allocator keeps. Rewriting the UI won't move it.

**Engine switches** (private WebKit API; each is checked before use and
reported by the browser):

| Setting | Default | Evidence |
|---|---|---|
| `prewarm` (start a spare page process ahead of time) | **off** | 5 → 4 processes, −9 MB idle. Our custom process pool *added* a prewarmed process, so this setting is required. |
| `pagecache` (back/forward cache) | **off** | Cross-site 3-loop session: peak 1816 MB → 299 MB, held after loop 1: 337 → 137 MB. Back button 41 vs 43 ms. Caveat: the test pages send `no-store`, which WebKit never caches, so the Back test didn't see the cache. The back test needs a cacheable page; see Open items. |
| `proccache` (keep exited pages' processes for reuse) | on | No measurable effect. The re-test after the session went cross-site crashed, so it's not settled yet. |
| `jit` (JavaScript JIT) | **on** (setting) | Off: session end ~130 MB instead of ~230 MB, but the `compute` page took 266 → 708 ms (2.7× slower JS). Kept on because of the no-regression rule. It's a user setting ("Fast JavaScript"). Still waiting for the owner's decision. |
| `suspend` (suspend background processes under pressure) | off | Not measurable: the harness voids runs under memory pressure. |

**Tracker list** in `resources/trackers.bin`: the JSON is 6.5 MB, so it's
stored as raw DEFLATE (261 KB) and inflated with macOS's built-in
libcompression. That adds no dependency. Compiling takes ~0.8 s on first launch
and is cached by WebKit afterwards.

## Traps we hit (don't repeat them)

1. **Shared profile wiped the owner's login.** The bare binary used WebKit's
   default cookie file (`~/Library/HTTPStorages/my-browser.binarycookies`).
   Tests launched up to 9 browsers in parallel and they overwrote each other's
   cookie files. Now:
   - tests and benchmarks use throwaway or temp profiles,
   - the real profile is UUID-keyed and locked.

   **Never run the browser against the default profile from tests.**
2. **Hidden benchmark windows.** macOS opened bench windows behind a full-screen
   app or on another Space, and WebKit throttles and stops painting hidden
   pages. Every early bar missed all rendering cost. Now:
   - `--on-top` makes the app an accessory app with a floating window on all
     Spaces,
   - the harness asks `visible` at every measurement and voids the run if the
     window is hidden.

   Windows like that **can't be minimized** (a macOS rule).
3. **Measuring too soon.** WebKit frees ~12 MB in the page process 2–5 s after
   a load. Measuring at 2 s gave numbers that jumped between two values, so
   the settle time is now 6 s.
4. **Memory pressure** makes WebKit purge caches, so pages read 30–40% light.
   The harness voids those runs.
5. **WebKit helper processes aren't children of the app.** launchd spawns
   them, and their "responsible pid" is whatever launched the app (VS Code,
   Terminal). The harness matches helpers by three checks: same responsible
   pid, a `com.apple.WebKit.*` name, and a start time after the app's.
6. **Tracker list compile failure** (WKErrorDomain 6, no detail). One uppercase
   domain (`Wolt.com`) and URL-path entries (`yandex.ru/clck/click`) in
   `unless-domain` invalidated the whole list. The generator now lowercases
   everything and keeps only real hostnames.
7. **Throwaway profiles count as private browsing,** so WebKit doesn't run
   extensions there. Extension tests need `--profile <temp dir>`.
8. **Content scripts need tabs.** WebKit injects only into web views it knows
   as a `WKWebExtensionTab`. Our tabs implement it, and the app reports
   open/close/activate/change events.
9. **The title can arrive after "load finished".** WebKit sometimes delivers
   the page title after `didFinishNavigation`. Tests poll `state` with
   `state_until` instead of reading it once.
10. **Bad history titles.** The title KVO of a new page (empty) overwrote the
    previous page's history entry. Fix: the history link is reset on commit,
    and empty titles are never written.
11. **KVO on a destroyed web view crashes.** Remove observers before dropping a
    web view (`Tab::destroy_web`).
12. **Popup web views must use WebKit's configuration.**
    `createWebViewWithConfiguration` must return a web view built from exactly
    the configuration WebKit passes in.
13. **Benchmark windows stole keyboard focus.** The owner's typing in other
    apps went into the floating test browser: it opened tabs and showed up as
    30 ms/s "idle CPU" and 113 MB of GPU memory. Fixed: `--on-top` windows are
    never key and the app never activates. Tested in
    `bench_window_is_on_screen`. After the fix, a blank page totals 69 MB
    (bar 71), text 160 MB (bar 162), and our process uses 0 ms/s idle CPU.
14. **`ls` is aliased in the owner's shell** and can hang a scripted command.
    Use `/bin/ls`.
15. **Python from python.org has no certificates.** `scripts/update-trackers.py`
    downloads with `curl`.

   showed blank 69 MB, text 160 MB, our process 31 MB (bar 28: the

   (the earlier run died with "Broken pipe", probably from a window being
   closed by hand).
6. **Not built yet:**
   - find in page (Cmd+F),
   - the extension toolbar button and popup (`WKWebExtensionAction`),
   - tabs.onDetached/onAttached when a tab is dragged to another window,
   - per-site permission UI for camera/mic (WebKit's default prompt is used),

     pressure,
   - `WKWebView._setPageMuted` / suspend media in sleeping tabs,
   - a per-tab memory readout in the UI.

## How to verify everything quickly

```sh
cargo build --release
cargo test --release            # 43 tests, ~5 s; opens windows briefly
./target/release/bench --runs 1 # ~2 min; a floating window appears
./scripts/bundle.sh             # signed .app in target/release/
```
