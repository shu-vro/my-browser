# Iteration 1: security pass, site permissions, extensions off until clicked, native new tab page

## What changed

### Features the owner asked for
- **Uninstall** (Settings → Storage): lists every path it will delete
  (profile, WebKit data/caches for both app identities, preferences, saved
  state, old leftovers, the running `.app`), asks in the page and natively,
  clears site data through WebKit, deletes, exits. Refused unless running on
  the main profile, so tests and `--profile` runs can't wipe the owner's data.
- **Appearance** setting (system / light / dark) via `NSApp.appearance`.
- **New tab page**, native (`src/home.rs`): the owner's SHIRSHEN banner
  (drawn as rectangles), search field, most visited sites, each switchable.
- **Site permissions** (`permissions` table): camera, microphone, location,
  multiple downloads (asked, remembered), local network (blocked unless
  allowed), Shields (on unless turned down). Site button + menu left of the
  address bar; Settings → Site settings hub.
- **Extensions**: toolbar buttons and popups; off on every site until
  clicked, off again when the tab leaves the site; started (context loaded)
  only on first click; install asks first; runtime permission requests are
  prompts; right-click a button for "On every site".

### Brave-level protections (see DESIGN-DECISIONS "How does this compare with Brave")
- HTTPS first (WebKit `preferredHTTPSNavigationPolicy`, auto fallback).
- Global Privacy Control (WebKit, macOS 27).
- Safari's Advanced Tracking and Fingerprinting Protection
  (`_setNetworkConnectionIntegrityPolicy:` Enabled | EnhancedTelemetry |
  SanitizeLookalikeCharacters), off on Shields-down sites.
- Tracking-parameter stripping (Brave's default list).
- Local-network shield (second content-blocker list).
- Safari user-agent suffix (blend in).

### Holes found by attacking the browser, all fixed and tested
1. **Address-bar spoofing**: a page navigating itself to a slow site showed
   the new address over its own content. Now the committed address is shown
   (`_committedURL`). `address_bar_cannot_be_spoofed_by_a_slow_navigation`.
2. **Clickjacking internal pages**: a page iframe-ing `mybrowser://settings`
   could slip through if it raced a typed internal load (the one-shot
   `allow_internal` flag). Internal pages now load only in the main frame,
   carry `frame-ancestors 'none'`/`X-Frame-Options`, and `allow_internal`
   holds the exact address until commit/fail.
3. **`alert()` loops trapped the tab** (a window can't close with a sheet up).
   Second dialog offers "Don't allow more". `pages_cannot_trap_the_tab_with_dialogs`.
4. **Download floods**: unlimited automatic downloads. Second one per page asks.
5. **Right-to-left override file names** (`photo\u{202E}gpj.app`). Stripped.
6. **Crash-reload loop** burned CPU forever. Capped at 2 reloads / 30 s.
7. **Extensions could point tabs at `mybrowser:`/`file:`/`javascript:`.** Refused.
8. **No error page**: failed loads left the old page under a new address.
   Error page via `_loadAlternateHTMLString:…forUnreachableURL:`, escaped,
   no script, no certificate bypass.
9. **Profile folder world-readable** (umask): now `0700`.
10. **Bench output crashed the browser** when the reader went away
    (`println!` panics on EPIPE, release aborts): `say!` ignores it.
    `a_harness_that_stops_reading_does_not_crash_the_browser`.
11. **Flaky internal-page loads**: WebKit can decide one navigation twice
    (process swap); the one-shot flag cancelled the second. Fixed with #2.

Also: hardened runtime + camera/mic/location entitlements in `bundle.sh`
(verified on a scratch copy: signs as `adhoc,runtime`, launches, all TUNE ok).

## Traps found

- `WKWebView.URL` changes before commit for page-started navigations: never
  show it raw in the address bar.
- WebKit may call `decidePolicyForNavigationAction` more than once for one
  navigation; don't use one-shot flags there.
- WebKit's link decoration filtering acts on the page being *left*, so a
  Shields change needs a reload before it applies (the site menu reloads).
- `ignore-previous-rules` only reaches rules in its own content-rule list.
- WebKit already quarantines downloads (`0081;…;;UUID`); setting
  `NSURLQuarantinePropertiesKey` again does nothing (removed).
- `println!` panics on a closed stdout. In bench code use `say!`.
- `objc2` methods defined in `define_class!` can't be called directly from
  Rust (they take the selector); use `msg_send!`.
- Editing e2e.rs by slicing between two test names deleted the tests in
  between once. Check the test count after such edits (it's 36 e2e now).
